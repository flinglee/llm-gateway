# 我搭了一个「本机 LLM 网关」：白嫖阿里云 83 个免费模型，限流/额度耗尽自动切换，还顺便防烧钱

> 版本：v0.5.0 ｜ 完全开源，仓库见文末

## 一、痛点：调大模型，钱和额度是两笔糊涂账

很多做 AI 应用的朋友都踩过这几个坑：

- **调一次烧多少不知道**：今天被扣了 ¥39，回头一看是某个「Lite 套餐订阅订单」被误当成 API 消费，真正烧掉的才 ¥1 出头；
- **免费额度用没用完说不清**：阿里云百炼后台说有 83 个模型带免费额度，但网关路由时到底用没用上、还剩多少，全靠猜；
- **一限流就整条链路挂掉**：某个模型 429 了，重试逻辑傻乎乎地反复打同一个模型，结果不是超时就是连环报错；
- **Key 失效了还在反复试**：某把 Key 被百炼封了，请求照样一遍遍打过去，纯浪费。

我受够了，于是自己写了个**跑在本机的 LLM 网关**，把这些事一把梭了。

## 二、它是什么

一句话：一个兼容 OpenAI 协议的本地网关，你的应用把请求发给我，我来决定「用哪个模型、走不走免费、失败怎么兜底」。

```
你的应用  ──OpenAI 格式──▶  本机网关(8021)  ──▶  阿里云百炼 / 智谱 / 硅基流动 / DeepSeek …
                                    │
                                    ├─ 免费额度优先
                                    ├─ 限流/额度耗尽自动切模型
                                    └─ 控制台实时看余量 & 失败原因
```

对上层应用来说，**它就是一个「永远不花钱、永远不报 429」的大模型接口**。

## 三、核心能力

### 1. 白嫖免费额度，且“真·用上”

网关每天自动去百炼控制台把 83 个模型的免费额度拉回来（纯子进程，不卡主流程），路由时**优先用还有免费额度的模型**。我发现阿里云其实有上百个模型带免费额度——之前根本没被利用起来，现在自动登记、自动用完。

### 2. 防烧钱硬闸

- `allow_paid=false` 时，**任何付费模型都不进候选池**。你代码里哪怕写死 `qwen-max`，网关也透明替换成最便宜的免费等效模型，业务不中断、钱包不出血；
- 免费额度低于水位线（默认剩 2000 token）就自动切到付费包，不烧最后一滴免费 token 去触发百炼的 403。

### 3. 限流 / 额度耗尽 / Key 失效，自动分类处理

这是 v0.5.0 重点打磨的「统一错误分类层」：

| 上游报错 | 网关动作 |
|---|---|
| 免费额度耗尽 | 当期永久剔除该模型，不再反复重试失败 |
| 401/403 鉴权失败 | 冷却这把 Key（更久），不再反复打失效 Key |
| 429 限流 | 短冷却，换下一个候选 |
| 503 过载 | 短冷却，换下一个候选 |
| 网络/超时 | 短冷却，换下一个候选 |

冷却中的模型/Key 直接被路由排除，冷却到期后的**第一个请求就是唯一一次探测**——杜绝全量重试风暴。

### 4. 控制台一眼看穿

自带一个管理页面：

- 按「最近使用」排序的模型余量表；
- 每个 Key 的**失败类别**（限流 / 过载 / 鉴权失败 / 额度耗尽），出问题秒定位；
- 多平台官方余额（硅基流动、DeepSeek……可扩展）；
- 额度变动提醒（哪个模型又快用完了，主动告诉你）。

### 5. 缓存零花费

相同请求（低温度）命中缓存直接返回，不花一分钱，还记账「省了多少」。

## 四、技术上有意思的两点

- **Reactive 对齐**：百炼一旦报错说「这个模型免费额度没了」，网关立刻学到并永久停用它，下个请求绝不重蹈覆辙。
- **单探测恢复（single-probe recovery）**：借鉴了同类开源项目的思路——出问题的模型不是“每次请求都试一遍”，而是冷却期只放一个探子，通了就恢复，不通继续歇着。

## 五、怎么跑

```bash
pip install -r requirements.txt
# 在 .env 里填 BAILIAN_API_KEY 等（密钥全用环境变量，仓库不存明文）
python -m uvicorn app.main:app --host 0.0.0.0 --port 8021
```

应用侧把 `base_url` 指向 `http://localhost:8021/v1`，`api_key` 随便填（网关按身份路由），模型名写 `auto` 即可。
